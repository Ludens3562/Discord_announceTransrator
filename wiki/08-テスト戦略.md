# 🧪 8. テスト戦略

## テスト構成
- 単体テスト（`tests/`）: Provider 実装・Markdown 保護・TranslationService のロジック
- 統合テスト: Provider 切替と Embed 翻訳の振る舞い確認（モック利用）

## 実行方法
```bash
python -m pytest -q
```

## モック方針
- 外部 API 呼び出し（`deepl`, `googletrans`）は全てモックする
- Provider の単体テストは `sys.modules` 替えや `monkeypatch` を使用

## 重要テストケース（抜粋）
- `test_translation_pipeline.py` — Markdown 保護と復元の検証
- `test_embed_translation.py` — Embed 各部の翻訳を検証
- `test_google_provider.py` / `test_deepl_provider.py` — Provider の同期/非同期挙動
- `test_googleTrans_reply_not_mentioning_author.py` — 返信でメンションを行わないことの検証

## CI ルール（推奨）
- PR は必ず `pytest` を通過させること
- Provider に関する変更は外部 API 呼び出しをモックしたユニットテストを追加すること
