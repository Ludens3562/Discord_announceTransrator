# 翻訳パイプライン
`TranslationService` を中心とした翻訳処理の流れと、Markdown・メンションの保護方式、Embed の翻訳、プロバイダー切替、エラー処理を示す。実装は `app/translation_service.py` と `app/utils/markdown_helper.py` に基づく。

## 全体の流れ
テキスト翻訳は保護、翻訳、復元の3段階で処理する（`app/translation_service.py:67-93`）。

```mermaid
flowchart LR
    input[入力テキスト] --> protect["protect_text<br/>保護対象をプレースホルダ化"]
    protect --> call["プロバイダー呼び出し<br/>DeepL / Google"]
    call --> restore["restore_text<br/>プレースホルダを復元"]
    restore --> output[翻訳結果]
```

処理の順序は次のとおりである。

1. 入力が空文字の場合はそのまま返す。
2. `protect_text` で保護対象をプレースホルダに置換する。
3. `provider_name` からプロバイダーを決定する。指定が無い場合は登録された最初のプロバイダーを用いる。存在しないプロバイダー名の場合は `ProviderError` を投げる。
4. プロバイダーへ保護済みテキストを渡して翻訳する。
5. `restore_text` でプレースホルダを元の文字列へ戻す。

## Markdown とメンションの保護
翻訳エンジンが Markdown の構造、URL、メンションを破壊しないよう、翻訳前に保護対象をプレースホルダへ置換する（`app/utils/markdown_helper.py:19-116`）。

保護対象と適用順序を次に示す。適用順序が意味を持つため、コードブロックを最初に処理する。

| 順序 | 保護対象 | 例 | 正規表現の対象 |
| --- | --- | --- | --- |
| 1 | コードブロック | ` ```code``` ` | ` ```.*?``` `（改行を含む） |
| 2 | インラインコード | `` `code` `` | `` `[^`]+` `` |
| 3 | カスタム絵文字 | `<:name:id>` / `<a:name:id>` | `<a?:[^:>]+:\d+>` |
| 4 | メンション | `<@id>` / `<@&id>` / `<#id>` | `<@!?:?\d+>` ほか |
| 5 | URL | `https://...` | `https?://\S+` |

保護対象外（翻訳対象）は通常のテキストである。Markdown リンクの場合、URL は保護され、表示テキストのみが翻訳される。

### プレースホルダの生成
プレースホルダは種別、連番、6桁の数字サフィックスからなる（`app/utils/markdown_helper.py:8-15`）。サフィックスは `uuid.uuid4().int % 1000000` を6桁ゼロ埋めした値で、翻訳結果内での偶発的な衝突確率を下げる。形式は次のとおりである。

```text
__MD_<種別>_<連番>_<6桁数字>__
```

### 復元
`restore_text` はプレースホルダのキーで単純文字列置換を行い、元の Markdown 構造を復元する（`app/utils/markdown_helper.py:119-129`）。置換は長いキーから順に行い、部分一致による誤置換を避ける。

## Embed の翻訳
`translate_embed` は Embed の各テキスト要素を翻訳し、新しい Embed を返す（`app/translation_service.py:95-125`）。元の Embed は変更しない。

- 翻訳対象: `title`、`description`、`fields[*].name`、`fields[*].value`、`footer.text`。
- 維持する要素: 色（`colour`）、タイムスタンプ（`timestamp`）、フィールドの `inline` 指定。

`translate_message` は `discord.Message` の `content` と `embeds` をまとめて翻訳し、`{"content": ..., "embeds": [...]}` の辞書を返す（`app/translation_service.py:127-142`）。

## プロバイダー切替
`TranslationService` はプロバイダー名からインスタンスへの辞書を保持する。`translate_text` の `provider_name` 引数で使用するプロバイダーを指定する。

- bot は起動時に `_build_providers` で辞書を構築する。`DEEPL_API_KEY` があれば `deepl` を、`google` は常に登録する（`app/bot.py:60-78`）。
- 実際に使用するプロバイダー名は、監視チャンネル設定の解決結果（チャンネル上書き > ギルド既定 > 既定値 `deepl`）から決まる。解決の詳細は [データモデル](./05-データモデル.md) を参照する。

## 同時実行の制御
`TranslationService(max_concurrent=...)` を指定すると、`asyncio.BoundedSemaphore` でプロバイダー呼び出しの同時実行数を制限する（`app/translation_service.py:23-65`）。レート制限のあるプロバイダーへの過剰な同時呼び出しを抑える用途に用いる。既定（`None`）では制限しない。

## プロバイダー呼び出しの委譲
`_call_provider` はプロバイダーの非同期・同期実装を吸収する（`app/translation_service.py:31-65`）。

1. `translate_async` がコルーチンとして定義されていれば `await` する。
2. 無ければ同期 `translate` を `asyncio.to_thread` で別スレッド実行し、イベントループをブロックしない。
3. いずれも無ければ `ProviderError` を投げる。

## エラー処理
プロバイダー固有の失敗は `ProviderError` に統一して伝搬する（`app/providers/provider.py`）。

- `_call_provider` は `ProviderError` をそのまま再送出し、その他の例外は `ProviderError` に変換する。
- `translate_and_reply` は `ProviderError` を捕捉し、警告ログを出力して返信を行わない（ユーザーへは通知しない）。
- コマンドからの翻訳（`/translate manual`、`/translate test`）では `ProviderError` を捕捉し、実行者へエラーを通知する。詳細は [コマンドリファレンス](./08-コマンドリファレンス.md) を参照する。
