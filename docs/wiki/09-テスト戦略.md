# テスト戦略
テストの構成と方針を示す。テストは pytest を用い、`tests/` に配置する。外部依存（ネットワーク、データベース、外部翻訳 API）はフェイクで代替する。

## 実行方法
テストはコンテナ内で実行する。作業ディレクトリはリポジトリルートとする。

```bash
docker compose run --rm disbot -m pytest
```

`disbot` サービスのエントリーポイントは `python -u`（`Dockerfile`）であるため、`-m pytest` を引数として渡す。

## テスト構成
テストファイルと対象を次に示す。

| テストファイル | 対象 |
| --- | --- |
| `tests/conftest.py` | 共通フィクスチャ（`FakePool`、`fake_pool`） |
| `tests/test_provider_interface.py` | `Provider` 抽象の強制とフェイク実装 |
| `tests/test_provider_contract.py` | プロバイダー契約（成功・失敗、`ProviderError` の公開） |
| `tests/test_deepl_provider.py` | `DeepLProvider`（翻訳成功、キー未設定時の失敗） |
| `tests/test_google_provider.py` | `GoogleProvider`（同期・非同期の翻訳） |
| `tests/test_translation_pipeline.py` | 保護と復元、プレースホルダ保持、失敗時の例外、衝突処理 |
| `tests/test_embed_translation.py` | Embed の各要素の翻訳 |
| `tests/test_message_handler.py` | `translate_and_reply`（返信、監視対象外、空メッセージ） |
| `tests/test_config_repository.py` | `ConfigRepository` の CRUD と SQL 引数 |
| `tests/test_db_pool.py` | `create_pool` の環境変数不足・不正ポートの検証 |
| `tests/test_auth.py` | 権限チェック（オーナー、管理権限、DM、非メンバー） |

## テスト方針
テストは次の方針で記述する。

- 単体テストを中心とする。外部依存はフェイクやモンキーパッチで置き換え、実際のネットワークやデータベースには接続しない。
- 正常系と異常系の双方を検証する。例として、`DeepLProvider` は翻訳成功とキー未設定時の `ProviderError` を検証する。
- 共通のセットアップはフィクスチャに集約する。`FakePool` は `asyncpg.Pool` の最小フェイクで、呼び出された SQL と引数を記録し、あらかじめ設定した結果を返す（`tests/conftest.py`）。
- 例外は `pytest.raises` で検証する。

## フェイクの例
`FakePool` は SQL 呼び出しを記録し、戻り値を制御する（`tests/conftest.py:13-49`）。リポジトリのテストは、記録された SQL と引数を検証することで、実データベースなしに動作を確認する。

```python
# tests/conftest.py の抜粋（フェイクの接続プール）
class FakePool:
    async def fetchrow(self, sql: str, *args):
        self.calls.append(("fetchrow", sql, args))
        return self.fetchrow_result
```

`translate_and_reply` のテストでは、メッセージ、リポジトリ、翻訳サービスをフェイクで用意し、返信時に送信者へメンションしないこと、監視対象外・空メッセージで何もしないことを検証する（`tests/test_message_handler.py`）。
