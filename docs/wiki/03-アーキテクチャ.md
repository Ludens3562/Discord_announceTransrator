# アーキテクチャ
システム全体の構成、レイヤー間の関係、および主要な処理フローを示す。

## システム全体の構成
bot は Docker Compose の `disbot` サービスとして動作し、`db` サービス（PostgreSQL）と外部の翻訳 API に依存する。全体構成を次に示す。

```mermaid
flowchart LR
    user[Discord ユーザー] -->|メッセージ / スラッシュコマンド| discord[Discord Gateway]
    discord <-->|イベント / 応答| bot[disbot コンテナ<br/>TranslatorBot]
    bot -->|設定の読み書き| db[(PostgreSQL<br/>db コンテナ)]
    bot -->|翻訳要求| deepl[DeepL API]
    bot -->|翻訳要求| google[Google 翻訳]
    db -.->|永続化| volume[(pgdata ボリューム)]
```

## レイヤー構成
レイヤードアーキテクチャを採用し、各レイヤーの責務を分離する。上位レイヤーは下位レイヤーに依存する。

```mermaid
flowchart TD
    entry["エントリーポイント層<br/>app/main.py"]
    botlayer["bot 層<br/>app/bot.py（TranslatorBot）"]
    cmd["コマンド層<br/>app/commands/translate_group.py"]
    handler["メッセージ処理<br/>app/message_handler.py"]
    service["サービス層<br/>app/translation_service.py"]
    provider["プロバイダー層<br/>app/providers/*"]
    repo["永続化層<br/>app/db/repository.py"]
    util["ユーティリティ層<br/>app/utils/*"]

    entry --> botlayer
    botlayer --> cmd
    botlayer --> handler
    cmd --> service
    cmd --> repo
    handler --> service
    handler --> repo
    service --> provider
    service --> util
    cmd --> util
    repo --> db[(PostgreSQL)]
```

各レイヤーの責務は次のとおりである。

- エントリーポイント層: 環境変数を読み込み、`TranslatorBot` を生成して起動する（`app/main.py`）。
- bot 層: Discord イベントを受け取り、`setup_hook` で依存（接続プール、リポジトリ、翻訳サービス、コマンドツリー）を初期化する（`app/bot.py`）。
- コマンド層: スラッシュコマンドを定義し、リポジトリと翻訳サービスへ委譲する（`app/commands/translate_group.py`）。
- メッセージ処理: 監視対象メッセージを翻訳して返信する純粋な関数を提供する（`app/message_handler.py`）。
- サービス層: Markdown 保護、プロバイダー呼び出し、復元からなる翻訳パイプラインを提供する（`app/translation_service.py`）。
- プロバイダー層: 翻訳エンジンを `Provider` 抽象で統一する（`app/providers/`）。
- 永続化層: 設定の CRUD（作成、参照、更新、削除）を提供する（`app/db/repository.py`）。
- ユーティリティ層: Markdown 保護と権限チェックを提供する（`app/utils/`）。

## 初期化フロー
外部 I/O を伴う初期化は同期コンストラクタではなく、discord.py の非同期フック `setup_hook` で行う。起動から初期化完了までの流れを次に示す。

```mermaid
sequenceDiagram
    participant Main as main.py
    participant Bot as TranslatorBot
    participant Pool as db.pool
    participant Repo as ConfigRepository
    participant Svc as TranslationService

    Main->>Main: load_dotenv で app/.env を読み込む
    Main->>Bot: TranslatorBot() を生成（外部 I/O なし）
    Main->>Bot: bot.run(BOT_TOKEN)
    Bot->>Pool: create_pool()（接続プール生成）
    Bot->>Pool: init_schema()（テーブル冪等作成）
    Bot->>Repo: ConfigRepository(pool)
    Bot->>Svc: TranslationService(providers)
    Bot->>Bot: tree.add_command(TranslateGroup())
    Note over Bot: on_ready でコマンドを同期
```

## メッセージ翻訳フロー
`on_message` は監視対象チャンネルのメッセージを翻訳して返信する。処理の分岐を次に示す。

```mermaid
sequenceDiagram
    participant D as Discord
    participant Bot as TranslatorBot.on_message
    participant H as translate_and_reply
    participant Repo as ConfigRepository
    participant Svc as TranslationService

    D->>Bot: メッセージ受信
    Bot->>Bot: 送信者が bot 自身なら終了
    Bot->>H: translate_and_reply(message, repository, service)
    H->>H: ギルド外 / 空メッセージなら終了
    H->>Repo: get_channel_translation_settings(channel_id)
    Repo-->>H: 設定（監視対象外なら None）
    H->>H: None なら終了
    H->>Svc: translate_text(content, source, target, provider)
    Svc-->>H: 翻訳結果（失敗時は ProviderError）
    H->>D: message.reply(翻訳結果, mention_author=False)
```

翻訳失敗（`ProviderError`）や返信失敗（`discord.HTTPException`）は警告ログを出力して握りつぶし、ユーザーへは通知しない（`app/message_handler.py:46-63`）。

## コマンド処理フロー
スラッシュコマンドは `interaction.client`（`TranslatorBot` 実体）経由でリポジトリと翻訳サービスにアクセスする。権限チェックは `app_commands.check` デコレータで行い、失敗時は共通エラーハンドラ `handle_app_command_error` が日本語メッセージを返す（`app/commands/translate_group.py:509-529`）。詳細は [コアコンポーネント](./06-コアコンポーネント.md) と [コマンドリファレンス](./08-コマンドリファレンス.md) を参照する。
