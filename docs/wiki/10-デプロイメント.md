# デプロイメント
Docker を用いたビルドと起動、環境変数、データ永続化、トラブルシューティングを示す。作業ディレクトリはリポジトリルートとする。

## ビルドと起動
Docker Compose で PostgreSQL と bot を一括で起動する。

```bash
docker compose up -d --build
```

`db` サービスがヘルスチェックに合格した後に `disbot` サービスが起動する（`docker-compose.yml:15-17`）。bot は起動時に必要なテーブル（`guild_settings`、`monitored_channels`）を冪等に自動作成する。

停止する場合は次を実行する。ボリュームは保持される。

```bash
docker compose down
```

## サービス構成
`docker-compose.yml` は次の2サービスを定義する。

- `disbot`: bot 本体。`Dockerfile` からビルドする。`app/.env` を読み込み、タイムゾーンは `Asia/Tokyo`。ヘルスチェックは PID 1 が python プロセスであることを確認する。`restart: unless-stopped` で自動再起動する。
- `db`: PostgreSQL 16（`postgres:16-alpine`）。`app/.env` から `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` を読み込む。ヘルスチェックは `pg_isready` で行う。設定を名前付きボリューム `pgdata` に永続化する。

## コンテナイメージ
`Dockerfile` は `python:3.12-slim-bullseye` をベースとする。

- ロケール `ja_JP.UTF-8` とタイムゾーン `Asia/Tokyo` を設定する。
- `requirements.txt` を先にコピーして依存をインストールし、ビルドキャッシュを活用する。
- 非特権ユーザー `appuser`（UID 1000）で実行する。
- エントリーポイントは `python -u`、既定コマンドは `-m app.main` である。モジュールとして実行することでパッケージの相対インポートを解決する。

## 環境変数
必須および任意の環境変数を次に示す。値は `app/.env` に記述し、リポジトリにコミットしない（`.gitignore` 済み）。

| 環境変数 | 必須 | 説明 |
| --- | --- | --- |
| `BOT_TOKEN` | 必須 | Discord bot トークン |
| `DEEPL_API_KEY` | 条件付き | DeepL API キー。未設定時は DeepL プロバイダーを無効化する |
| `DEV_GUILD_ID` | 任意 | 設定するとそのギルドへコマンドを即時同期する。省略時はグローバル同期 |
| `POSTGRES_HOST` | 必須 | PostgreSQL ホスト名。Docker Compose 利用時はサービス名 `db` |
| `POSTGRES_PORT` | 任意 | PostgreSQL ポート番号。既定は `5432`。整数で指定する |
| `POSTGRES_USER` | 必須 | PostgreSQL ユーザー名 |
| `POSTGRES_PASSWORD` | 必須 | PostgreSQL パスワード |
| `POSTGRES_DB` | 必須 | PostgreSQL データベース名 |

`disbot` と `db` の両サービスが `app/.env` を読み込む。本番環境では Docker secrets やオーケストレータのシークレット管理の利用を推奨する。

## データの永続化
設定は PostgreSQL に保存され、名前付きボリューム `pgdata` に永続化される。`docker compose down`（`-v` を付けない）ではボリュームは保持される。データを完全に削除する場合のみ次を実行する。

```bash
docker compose down -v
```

API キーや機密情報はデータベースには保存せず、`app/.env` または環境変数で管理する。旧バージョンの JSON ファイル（`config.json` / `channels.json`）からの移行スクリプトは提供しない。設定はスラッシュコマンドで再登録する。

## トラブルシューティング
発生しやすい事象と対処を示す。

- 事象: bot 起動時に `データベース接続に必要な環境変数が設定されていません` というエラーで終了する。
  - 原因: `POSTGRES_HOST` / `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` のいずれかが未設定である。
  - 対処: `app/.env` に該当する環境変数を設定して再起動する。
- 事象: bot 起動時に `POSTGRES_PORT が整数ではありません` というエラーで終了する。
  - 原因: `POSTGRES_PORT` に整数でない値を設定している。
  - 対処: `POSTGRES_PORT` を整数（既定 `5432`）に設定する。
- 事象: `disbot` が `db` に接続できず起動を繰り返す。
  - 原因: `POSTGRES_HOST` がサービス名 `db` になっていない、または `db` サービスがヘルスチェックに合格していない。
  - 対処: `app/.env` の `POSTGRES_HOST=db` を確認し、`docker compose ps` で `db` が `healthy` であることを確認する。
- 事象: `BOT_TOKEN が設定されていません。` というログを出力して起動しない。
  - 原因: `BOT_TOKEN` が未設定である。
  - 対処: `app/.env` に `BOT_TOKEN` を設定して再起動する。
- 事象: スラッシュコマンドが Discord クライアントに表示されない。
  - 原因: グローバル同期の反映には最大1時間かかる場合がある。
  - 対処: `DEV_GUILD_ID` を設定して開発ギルドへ即時同期するか、bot オーナーが `/translate sync` を実行する。
